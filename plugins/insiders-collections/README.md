# INSIDERS Collections, מערכת תשלומים וגבייה (תוסף וורדפרס)

גרסה 0.3.0. מימוש של [האפיון, גרסה 1.3](docs/spec/collections-spec-v1.3.md).

התוסף מטפל בשלושה מסלולים:
- חיובים חוזרים של My Billing בטרנזילה שלא עברו;
- התוכנית למתחילים: ליווי אוטומטי לפני המועד לפי הנוהל, אישור יומי של החיובים אחרי המועד, וזיכוי למי שפתח חשבון אחרי תשלום;
- המשך טיפול בלקוחות שכבר קיבלו פניות.

**ברירת המחדל בטוחה.** אחרי ההתקנה מתג העצירה פעיל, מצב תצוגה בלבד פעיל, וכל היכולות החיצוניות כבויות. כל עוד לא שיניתם את זה, התוסף לא שולח הודעות, לא יוצר קישורי תשלום ולא נוגע בטרנזילה מעבר לקריאה.

**הנתונים נפתחים רק בסריקה.** כניסה לוורדפרס לבדה לא מציגה כלום. המערכת נפתחת אחרי סריקת QR מטלפון מחובר ואישור בזיהוי פנים, טביעת אצבע או קוד הנעילה של הטלפון. הפירוט בסעיף ״שער הסריקה״ בהמשך.

## התקנה, לפי הסדר

1. **העלאה והפעלה.** תוספים ← הוספת תוסף ← העלאת קובץ ה־zip ← הפעלה.
2. **בלי עריכת קבצים.** מפתח ההצפנה נוצר אוטומטית בקובץ `wp-content/icol-encryption-key.php`. אין למחוק אותו: בלעדיו צריך להזין מחדש את מפתחות הספקים. הקובץ נכלל בגיבויים של Cloudways. אם התיקייה לא ניתנת לכתיבה, מסך הבריאות מראה `encryption: false`, וכלי האבחון `genkey` נותן שורה ל־`wp-config.php`.
3. **בדיקות אחרי העלאה, לפי הסדר:** `syntax`, אחר כך `schema`, אחר כך `health` ו־`gate`. הקישור ״כלי אבחון והתקנה״ נמצא בתחתית מסך הנעילה. כל הכלים עובדים ב־GET, כי ModSecurity ב־Cloudways חוסם POST. שאר הכלים מציגים נתונים, ולכן הם עובדים רק אחרי שלב 4.
4. **חיבור הטלפון.** פותחים את ״תשלומים וגבייה״. בהגדרה הראשונה מנהל האתר לוחץ ״להגדיר אותי כבעלים של המערכת״ ומזין את סיסמת וורדפרס. אחר כך סורקים את הקוד במצלמה של הטלפון, או בכל סורק QR שפותח את הקישור בספארי או בכרום. בטלפון נותנים שם למכשיר ומאשרים יצירת מפתח בזיהוי פנים או בטביעת אצבע. הטלפון מציג קוד בן שש ספרות, ואותו מקלידים במחשב. אחרי זה סורקים פעם נוספת כדי להיכנס. **מומלץ לחבר מיד גם טלפון גיבוי**, ב״אבטחה וטלפונים״ ← ״חיבור טלפון נוסף״.
5. **Cron של השרת.** ב־Cloudways ← Cron Job Management, הוסיפו משימה שרצה כל דקה. את השורה המדויקת מעתיקים מ״הגדרות ובריאות״:
   ```
   curl -s "https://<האתר>/wp-json/icol/v1/cron/tick?key=<מפתח>" > /dev/null
   ```
   חכו שתי דקות, וודאו שב״בריאות המערכת״ זמן ההצלחה של `tick` מתעדכן. רק אחרי זה אפשר לשקול `DISABLE_WP_CRON`.
6. **צוות.** ב״הגדרות ← צוות והרשאות״ קובעים לכל משתמש תפקיד: צופה, נציג, אחראי גבייה או מנהל. התפקיד נשמר בנפרד מתפקיד הוורדפרס, ולא משנה את הסיווג של המשתמש בתוספים אחרים. כל איש צוות מחבר את הטלפון שלו ממסך הנעילה, והטלפון ממתין לאישור שלך ב״אבטחה וטלפונים״.
7. **מדיניות פנייה.** ב״הגדרות ← מדיניות פנייה״ בודקים את השעות, הקצב, המכסות ולוח החגים, ומאשרים גרסה. בלי גרסה מאושרת לא יוצאות הודעות.
8. **חיבורים.** ב״הגדרות ← חיבורים״:
   - **טרנזילה.** מזינים app key ו־secret, ומריצים את כלי האבחון `tranzila_auth` כדי לקבוע את סדר החתימה. ב־My Billing ← Transaction Notification Endpoint מגדירים את הכתובת שמוצגת במסך הבריאות.
   - **WATI.** מזינים כתובת API, token ו־channel_number, מגדירים את כתובת ה־webhook שמוצגת במסך, ומגישים את התבניות לאישור מטא. שמות התבניות נשמרים ב״הגדרות ← תבניות״.
   - **פייפדרייב.** נדרש כדי למשוך טלפון ומייל של מועמדים מדשבורד ההכנסות, ולפתוח משימות על דיל ההצטרפות.
   - **Anthropic.** אופציונלי.
9. **דשבורד ההכנסות.** אם התוסף insiders-finance-dashboard פעיל, החיבור אוטומטי. מריצים את `revenue_probe` ובודקים שלושה דברים: `source_in_use` הוא `finance_dashboard`, `stale` הוא `false`, ול־`penalty_gross` יש מחיר. אם אין מחיר, צריך להגדיר בדשבורד את מוצר הקנס.
10. **התוכנית למתחילים.** ראו את הסעיף הבא. הליווי כבוי עד שמפעילים אותו.
11. **מדידה לפני הפעלה.** משאירים מצב תצוגה בלבד שבועיים לפחות, על האירועים האמיתיים. בודקים את הודעות הסימולציה בציר הזמן של התיקים. רק אז מכבים את מתג העצירה ומפעילים משלוחים.

## התוכנית למתחילים

1. **פייפדרייב.** יוצרים סיבת lost בשם ״לא מעוניין לפתוח חשבון״ ותווית דיל בשם ״ללא דמי רישום״. בצוות והרשאות מזינים לכל נציג את מזהה המשתמש שלו בפייפדרייב, כדי שמשימות השיחה יגיעו אליו.
2. **תבניות.** מגישים ב־WATI את הנוסחים מ־[docs/program-messages.md](docs/program-messages.md), ואחרי אישור של מטא מזינים את שמות התבניות ב״הגדרות ← תבניות״.
3. **הגדרות ← תוכנית למתחילים.** מתעדים על מה מבוססת ההרשאה לפנות לתלמידים (סעיף בהסכם), בודקים את המחירון (`2026-01-01 980 100`: תאריך תחולה, מחיר מלא, דמי רישום), ומפעילים את הליווי.
4. **בדיקה.** כלי האבחון `program` מראה בלי לכתוב דבר את ההגדרות, את התווית שנמצאה בפייפדרייב ואת מי שייכנס לליווי בריצה הבאה.
5. **כל יום.** ״תוכנית למתחילים ← אישור חיובים״: מסמנים ומאשרים. כל תלמיד נבדק שוב מול הדשבורד ברגע האישור.
6. **לפני 1.8.** ״תוכנית למתחילים ← ייבוא תלמידים״: מעתיקים מאקסל מספר דיל ותאריך הסכם, בודקים ומייבאים.

הריצה היא פעם בשעה, ובמצב תצוגה בלבד ההודעות מתועדות בציר הזמן ולא נשלחות.

## שער הסריקה

- **מה נחסם:** כל מסך של המערכת, כל קריאת API וכל כלי אבחון שמציג נתונים. האכיפה נעשית בשרת, בהרשאות עצמן. כל עוד אין חיבור פתוח, להרשאות של המשתמש אין תוקף.
- **מה לא נחסם:** דף התשלום של הלקוח, ה־webhooks של טרנזילה ו־WATI, נקודת ה־cron ו־WP-CLI.
- **משך חיבור:** 30 דקות בלי פעילות, ולכל היותר 8 שעות. אפשר לשנות ב״אבטחה וטלפונים״. רק בעל המערכת רואה את ההגדרה הזו.
- **טלפון של איש צוות:** ממתין לאישור של בעל המערכת. מנהל אחר לא יכול לאשר טלפונים.
- **כתובת:** נדרש https.

### טלפון אבד

1. אם יש טלפון גיבוי, סורקים איתו, נכנסים ל״אבטחה וטלפונים״ ומנתקים את הטלפון שאבד.
2. אם אין טלפון גיבוי, מוסיפים ל־`wp-config.php` את השורה `define( 'ICOL_GATE_OFF', true );`. המערכת נפתחת בלי סריקה, עם פס אזהרה, ונשלח מייל לבעל המערכת.
3. מנתקים את הטלפון שאבד ומחברים טלפון חדש.
4. **מוחקים את השורה מ־`wp-config.php`.**

## מה קיים בגרסה הזו

| תחום | מה בנוי |
|---|---|
| ספר תנועות | יתרות באגורות. שיוכים, התאמות והיפוכים כתנועות נפרדות, עם נעילת שורות וטרנזקציות. בדיקה יומית שהיתרה השמורה שווה לסכום התנועות |
| מצבים | שלושה צירים נפרדים: כספי (פריט), טיפול (תיק) וכרטיס (הוראה). כל מעבר עם גרסה ויומן |
| טרנזילה | קליטת My Billing ו־Notify, אימות מול דוח העסקאות, שלוש שיטות לזיהוי מחזור, התאמות עם דפדוף, בקשות תשלום (כבוי) |
| WATI | תבניות והודעות שירות, סטטוסי מסירה, קליטת תשובות, הודעות נציג, בעלות על השיחה |
| תשובות | כללים קבועים לכוונות שמחייבות עצירה. הצעות AI לנציג (כבוי), עם בדיקת שרת שדוחה סכומים והנחות שהמודל המציא |
| תזמון | ימי עבודה, חגים וימי זיכרון, מכסות ברמת הלקוח, המתנה לפי סוג כשל, חלוקה מחדש של פעולות אחרי השבתה |
| כרטיסים | משימות עדכון, ״אושר ידנית״ בנפרד מ״אומת מול ספק״, צפייה בטוקן עם אימות סיסמה ויומן |
| ממשק | לוח גבייה, תיקים, כרטיס תיק, חוב חדש, המשך טיפול, תור חריגים, כרטיסים לעדכון, מועמדים, משימות, הגדרות ובריאות |
| דף תשלום | `/pay/<token>` לפי העיצוב של המעצב (INSIDERS Design System). מציג מצב בלבד, והבקשה לטרנזילה נוצרת רק בלחיצה, אחרי בדיקת יתרה טרייה. ב״הגדרות ← חיבורים״: מספר הוואטסאפ, מראה כהה או בהיר, וקישור להצהרת הנגישות של האתר |
| שער סריקה | QR ומפתח גישה (passkey) בטלפון. בחירת מספר, אישור טלפונים על ידי בעל המערכת, נעילה בחוסר פעילות, מסך ״אבטחה וטלפונים״ |
| דשבורד ההכנסות | קריאה ישירה של שעון 90 הימים מ־insiders-finance-dashboard. טלפון ומייל מפייפדרייב, מחיר הקנס כהצעה, עצירה כשהסנכרון לא עדכני, ומשימה לרישום התשלום בדיל |
| התוכנית למתחילים | ליווי לפי המועד (45, 30, 14, 7, 3 ימים ויום המועד) עם שלושה לחצנים, מסלול ייעודי למי שסירב (לחצן או סיבת lost), מחיר לפי תאריך ההסכם ותווית דמי רישום, אישור יומי בפעולה אחת, חלון זיכוי, וייבוא תלמידים מלפני 1.8 |

## בדיקות

45 בדיקות הקבלה מהאפיון (AT01–AT45), עשר בדיקות נוספות (X01–X10), חמש בדיקות לשער הסריקה (G01–G05) ותשע לתוכנית למתחילים (P01–P09). הן רצות בוורדפרס אמיתי מול מסד נתונים אמיתי, וקריאות הספקים מדומות. X09 ו־P01 עד P08 צריכות את התוסף insiders-finance-dashboard פעיל באתר הבדיקה:

```
wp eval-file wp-content/plugins/insiders-collections/tests/run.php          # הכול
wp eval-file wp-content/plugins/insiders-collections/tests/run.php AT1      # סינון לפי מזהה
```

**הבדיקות מוחקות את כל טבלאות התוסף.** יש להריץ אותן רק בסביבת בדיקה, לעולם לא באתר החי.
